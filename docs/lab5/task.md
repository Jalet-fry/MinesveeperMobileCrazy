# Лабораторная работа №5: «Технический долг. Устранение долга»

## Что такое технический долг
*   [The solution to technical debt](http://blog.crisp.se/2013/07/12/henrikkniberg/the-solution-to-technical-debt)
*   [Good and bad technical debt](http://blog.crisp.se/2013/10/11/henrikkniberg/good-and-bad-technical-debt)
*   [ATDD для его устранения](https://www.infoq.com/articles/atdd-from-the-trenches)

## Признаки технического долга на проекте
*   Непонятный / нечитабельный код.
*   Дублирующийся код.
*   Отсутствие автоматизации (тестов, сборки, развёртывания).
*   Запутанная архитектура и ненужные сложные зависимости.
*   Медленные / неэффективные средства.
*   Незакоммиченый код / долгоживущие ветки.
*   Отсутствие / несоответствие технической документации.
*   Отсутствие тестовой среды.
*   Длинные циклы интеграции / отсутствие непрерывной интеграции.

## Критерии приемки (Definition of Done)
Один из способов борьбы с долгом — введение общих критериев:
1.  Код чистый.
2.  В продакшене.
3.  Принято пользователем (протестировано на пользовательских сценариях — пункт «Как продемонстрировать» в описании User Story).

## Задание на работу
1.  **Проинспектировать проект** на наличие технического долга (привести аргументы по каждому из пунктов «Признаков»).
2.  **Разработать план мероприятий** по его устранению.
3.  **Оценить план мероприятий**.
4.  **Сравнить объем долга** и недоимплементированных фич.
5.  **Сделать выводы** и обосновать необходимость (или отсутствие таковой) устранения долга, внести коррективы в план разработки проекта.
6.  **Представить на проверку** краткий отчёт и изменения плана.
