# Отчет по Лабораторной работе №5: «Технический долг»

## 1. Инспекция проекта на наличие технического долга

| Признак | Оценка и аргументация |
| :--- | :--- |
| **Непонятный код** | `Compression.kt` содержит низкоуровневую работу с битами и магические числа, что затрудняет поддержку. |
| **Дублирование** | В `MinesveeperEngine` и `LevelSettings` наблюдается избыточность параметров генерации. |
| **Автоматизация** | Unit-тесты покрывают только базовые сценарии. Отсутствуют UI-тесты и CI/CD. |
| **Архитектура** | На этапе Lab 3 выявлено «протекание» логики из Domain в UI (ViewModel слишком тесно связана с состоянием Engine). |
| **Документация** | Файл `ToDo.md` частично устарел и не отражает текущий статус всех уровней. |

## 2. План мероприятий по его устранению
1. **Рефакторинг `Compression.kt`**: Выделение логики парсинга дерева в отдельные методы, замена магических чисел на константы.
2. **Инверсия зависимостей**: Внедрение интерфейса репозитория для уровней, чтобы UI не зависел от способа хранения (DIP).
3. **Расширение тестового покрытия**: Написание тестов для экстремальных размеров полей (50x50) и всех типов анти-мин.

## 3. Оценка плана
План требует около 12-16 человеко-часов. Основная сложность — рефакторинг движка без поломки существующей логики 31 уровня.

## 4. Сравнение объема долга и недоимплементированных фич
Объем технического долга оценивается в **20%** от текущего кодовой базы. Приоритет устранения — высокий, так как это блокирует внедрение онлайн-рейтингов.

## 5. Выводы
Устранение долга критически необходимо для дальнейшего масштабирования проекта. Внесены коррективы в план: следующая итерация будет полностью посвящена рефакторингу.
