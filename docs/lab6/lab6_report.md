## 1 ОЦЕНКА ПО ПО АТРИБУТАМ КАЧЕСТВА USABILITY (ISO/IEC 25010:2011)

### 1.1 Распознаваемость соответствия (Appropriateness Recognizability)
**Оценка: 8/10**
- **До:** Поле сапера узнаваемо, но специфика (мульти-мины) была неявной.
- **После:** Внедрены уникальные иконки для каждого типа мин и соответствующих им флагов. Пользователь мгновенно распознает правила игры.

### 1.2 Обучаемость (Learnability)
**Оценка: 8/10**
- **До:** Логика переключения между 4 типами флагов была утомительной для классических уровней.
- **После:** **Smart Flagging** (автоматическое определение количества доступных типов) и тактильный отклик позволяют игроку освоиться без чтения мануалов.

### 1.3 Используемость / Операбельность (Operability)
**Оценка: 9/10**
- **До:** Неудобное управление на больших полях, отсутствие обратной связи.
- **После:** Реализован **Pinch-to-zoom** с сохранением плавности, вынесен инструмент быстрого переключения (Dig/Flag) и добавлена кнопка центрирования камеры.

### 1.4 Защита от ошибок пользователя (User Error Protection)
**Оценка: 8/10**
- **До:** Случайные нажатия при паузе или неверные "аккорды" никак не сигнализировались.
- **После:** Блокировка ввода в режиме паузы, **Haptic Error** (вибрация) при попытке вскрыть область без нужного количества флагов.

### 1.5 Эстетика GUI (User Interface Aesthetics)
**Оценка: 8/10**
- **До:** Статичные элементы, отсутствие акцентов на важных событиях.
- **После:** Анимированная красная вспышка при взрыве, использование Material 3 Surface для панелей управления, динамическая индикация текущего инструмента.

### 1.6 Доступность (Accessibility)
**Оценка: 9/10**
- **До:** Тексты зашиты в коде (Hardcode), отсутствие тактильного слоя.
- **После:** **Полная интернационализация** (все строки в `strings.xml`), поддержка системных настроек шрифтов и вибрационный фидбек для людей с нарушениями зрения.

## 2 ПУТИ УЛУЧШЕНИЯ UX И АРХИТЕКТУРЫ (TO-BE)

### 2.1 Архитектурная декомпозиция (Уровень структуры)
Согласно целевой модели (To-Be), логика доступа к данным уровней была отделена от UI через паттерн **Repository**.
- Создан интерфейс `IGameRepository`.
- Реализован `GameRepositoryImpl`.
Это устранило прямую зависимость View от Data Layer, сделав UX более стабильным при изменении источников данных.

### 2.2 Переход на ресурсную модель (Уровень поверхности)
Устранение Hardcode позволило привести приложение к стандартам Google Usability. Теперь интерфейс готов к локализации и корректно обрабатывается Screen Reader-ами.

### 2.3 Система метрик (Уровень стратегии)
Внедрен расчет **Efficiency (cells/click)**. Это дает игроку аналитический инструмент для оценки своего мастерства, что повышает вовлеченность (Retention).

## 5 ВЫВОДЫ

В ходе лабораторной работы приложение "Crazy Minesweeper" было доработано до соответствия современным стандартам мобильного UX. Основное внимание было уделено **Доступности** и **Операбельности**. Переход на архитектуру "To-Be" позволил чисто внедрить новые UX-фичи, не нарушая логику движка. Приложение стало более отзывчивым, информативным и готовым к масштабированию.
